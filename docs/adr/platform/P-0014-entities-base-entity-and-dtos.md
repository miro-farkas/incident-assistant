# P-0014: Logic-free entities, BaseEntity and DTOs

- Status: Accepted
- Date: 2026-10-18

## Context
With the layered structure (P-0013), entities, data access and business logic are separate
layers. Entities should be plain persistent state with one convention for ids, timestamps
and versions, and services should never expose them.

## Decision
- **Entities contain no logic**: fields with JPA mapping annotations, the default no-arg
  constructor (mappers create entities with it), getters and setters. No factory methods,
  validation, state checks or mapping methods; all rules live in the `service` layer.
  Generated values have getters only.
- **`BaseEntity`** (`@MappedSuperclass` in `model`), extended by every entity:

  | Field | Column | Notes |
  |---|---|---|
  | `id` | `id uuid` | UUIDv7, generated by Hibernate (`@UuidGenerator(style = VERSION_7)`): time-ordered, good index locality |
  | `createdAt` | `created_at timestamptz` | set on insert, never updated |
  | `updatedAt` | `updated_at timestamptz` | set on insert and on every update |
  | `version` | `version bigint` | `@Version`, optimistic locking |

  Timestamps are generated by Hibernate from the JVM clock (`@CreationTimestamp` /
  `@UpdateTimestamp`, default `SourceType.VM`). Hibernate rounds them to the column precision
  (microseconds for PostgreSQL `timestamptz`), so a DTO built from a just-written entity
  equals the same row reloaded later. Instances' clocks must be NTP-synchronised; ordering
  never relies on timestamps.
- **Append-only tables also extend `BaseEntity`** for uniformity; their `updated_at` and
  `version` stay at the insert values. An outbox table (P-0003) additionally has a
  `sequence_number bigint generated always as identity` column for the relay, because
  UUIDv7 is only time-ordered per JVM, not across instances.
- **DTOs**: immutable records in `dto`, used for every service input and output. Services
  never return entities and never accept them as parameters. Validation of DTO content stays
  in record compact constructors (it is input validation, not entity logic).
- **Mapping**: hand-written mapper classes in `mapper`, one per entity or event,
  application-scoped CDI beans with plain methods. No mapping library.
- **State setters** of workflow entities are called only from the `service` layer (ArchUnit
  rule), so every state change passes the state machine (P-0001).

## Alternatives considered
- `BaseEntity` only on mutable entities: avoids unused `updated_at`/`version` columns on
  append-only tables, but gives two id and timestamp conventions.
- Timestamps set by services from an injected `Clock`: testable with a fixed clock, but
  every write path must remember to set them.
- Timestamps generated by the database (`SourceType.DB`): one clock for all instances, but
  breaks optimistic locking in Hibernate 7.4. The UPDATE reads the generated `updated_at`
  back with `RETURNING`; when the version check matches no row, Hibernate fails with "The
  database returned no natively generated values" instead of `OptimisticLockException`, so
  concurrent updates are no longer reported as conflicts.
- MapStruct: less mapping code, but an annotation processor outside the Quarkus BOM, and
  generated code to debug for a handful of small mappings.
- Returning entities from services (open-session-in-view): least code, but leaks lazy
  loading and persistence state into resources and messaging (P-0013).

## Consequences
- Append-only entities are not mapped `@Immutable`: Hibernate cannot apply the `@Version`
  write lock to read-only entities. Repositories of append-only tables only insert.
- `createdAt` and `updatedAt` of a new row are generated separately and may differ by a
  microsecond; `updatedAt >= createdAt` always holds.
- Not in scope: auditing who changed a row (`created_by`), soft deletes, multi-tenancy.
