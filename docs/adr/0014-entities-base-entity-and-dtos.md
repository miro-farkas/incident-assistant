# ADR-0014: Logic-free entities, BaseEntity and DTOs

- Status: Accepted
- Date: 2026-10-18

## Context
With the layered structure (ADR-0013), entities, data access and business logic are separate
layers. In the INC-002 code, entities still contained behaviour (`IncidentEntity.received`,
`transitionTo` calling the state machine, `toDomain`), and each entity declared its own id,
timestamps and version. The maintainer wants entities to be plain persistent state, a common
base entity, and services that never expose entities.

## Decision
- **Entities contain no logic**: fields with JPA mapping annotations, the default no-arg
  constructor (mappers create entities with it), getters and setters. No factory methods,
  validation, state checks or mapping methods. All rules (state machine, reason codes,
  step/state compatibility) are applied in the `service` layer. Generated values (`BaseEntity`
  fields, `outbox_event.sequence_number`) have getters only.
- **`BaseEntity`** (`@MappedSuperclass` in `model`), extended by every entity:

  | Field | Column | Notes |
  |---|---|---|
  | `id` | `id uuid` | UUIDv7, generated by Hibernate (`@UuidGenerator(style = VERSION_7)`): time-ordered, good index locality |
  | `createdAt` | `created_at timestamptz` | set on insert, never updated |
  | `updatedAt` | `updated_at timestamptz` | set on insert and on every update |
  | `version` | `version bigint` | `@Version`, optimistic locking |

  Timestamps are generated by Hibernate from the JVM clock (`@CreationTimestamp` /
  `@UpdateTimestamp`, default `SourceType.VM`). Hibernate rounds them to the column precision
  (microseconds for PostgreSQL `timestamptz`), so a DTO built from a just-written entity equals
  the same row reloaded later. Instances' clocks must be NTP-synchronised; ordering never
  relies on timestamps (the version and `sequence_number` columns do that).

  *Refined during implementation:* the ADR first chose database-generated timestamps
  (`SourceType.DB`). With Hibernate 7.4 that breaks optimistic locking: the UPDATE reads the
  generated `updated_at` back with `RETURNING`, and when the version check matches no row
  Hibernate fails with "The database returned no natively generated values" instead of an
  `OptimisticLockException`, so concurrent updates are no longer reported as conflicts.
- **Append-only tables also extend `BaseEntity`** for uniformity: `incident_step` and
  `outbox_event` gain `updated_at` and `version`, which stay at their insert values because
  those rows are never updated. `outbox_event` keeps an additional `sequence_number bigint
  generated always as identity` column for the relay, because UUIDv7 is only time-ordered
  per JVM, not across instances. The number is assigned at insert, not commit, so it has
  gaps and is not a global commit order; per incident it increases, because writes to one
  incident are serialised by its row lock and version check, which is the order ADR-0004
  requires (events keyed by incident id). `event_id` stays a separate
  column, because the event id is part of the payload and is created before the row.
- **DTOs**: immutable records in `dto`, used for every service input and output. Services
  never return entities and never accept them as parameters. Validation of DTO content stays
  in record compact constructors (it is input validation, not entity logic).
- **Mapping**: hand-written mapper classes in `mapper`, one per entity, application-scoped
  CDI beans with plain methods. No mapping library.
- **Schema**: `V1__incident_schema.sql` is edited in place; no `V2` migration. Nothing has
  been deployed, so no database holds a `V1` that would need to migrate forward. From the
  first deployment on, applied migrations are immutable and every schema change is a new
  version.

## Alternatives considered
- `BaseEntity` only on mutable entities (`incident`, `approval_decision`): avoids unused
  `updated_at`/`version` columns on append-only tables, but gives two id and timestamp
  conventions. Rejected for uniformity; the cost is two unused columns per append-only row.
- Timestamps set by the service from an injected `Clock`: testable with a fixed clock, but
  every write path must remember to set them, and JVM clocks differ between instances.
- Timestamps generated by the database (`SourceType.DB`): one clock for all instances, but
  breaks optimistic-lock conflict detection in Hibernate 7.4 (see the refinement note above).
- MapStruct: less mapping code, but an annotation processor outside the Quarkus BOM, and
  generated code to debug for a handful of small mappings.
- Returning entities from services (open-session-in-view): least code, but leaks lazy
  loading and persistence state into resources and messaging, which ADR-0013 forbids.

## Consequences
- The state machine moves from `IncidentEntity.transitionTo` into the service layer;
  ADR-0001's "enforced on every change" now relies on all state changes going through
  `IncidentService`. An ArchUnit rule restricts calls to `Incident.setState` to the
  `service` package.
- Event `occurredAt` is the incident's generated `updatedAt` (`createdAt` for the creation
  event), so the event and the incident row carry the same instant and no `Clock` bean is
  needed.
- `incident_step` is not mapped `@Immutable`: Hibernate cannot apply the `@Version` write
  lock to read-only entities. Append-only is guaranteed by the repository, which only inserts.
- `createdAt` and `updatedAt` of a new row are generated separately and may differ by a
  microsecond; `updatedAt >= createdAt` always holds.
- Local dev and test databases created from the old `V1` fail Flyway validation (checksum
  mismatch). Dev Services start a fresh container per run, so this only affects a manually
  reused database, which has to be dropped once.
- `outbox_event.id` changes from bigint identity to UUID; INC-003's relay orders by
  `sequence_number`. The ADR-0012 event format is unchanged.
- `approval_decision.decided_at` is replaced by `created_at`.
- `IncidentDto` gains no new fields; `createdAt`/`updatedAt` now come from the database.
- Not in scope: auditing who changed a row (`created_by`), soft deletes, multi-tenancy.
